# zolo-sdk

Developer handoff: [project goal and current state](docs/project-handoff.md), [remaining work](docs/project-roadmap.md), [developer setup](docs/developer-guide.md), and [self-contained agent instructions](AGENTS.md). Root remains 0.46.0; the unfinished 0.47 candidate is preserved separately under `work-in-progress/`. Full installed-client parity remains open.

Repository: [WilsonLe/zolo-sdk](https://github.com/WilsonLe/zolo-sdk). The npm package name remains `zalo-personal-sdk`.

Node.js 22+ SDK for a Zalo user account. It signs in with a QR that the user approves on their phone, restores saved sessions, and exposes the full typed API and realtime listener from a locally patched, pinned [zca-js 2.2.0 transport](https://github.com/RFS-ADRENO/zca-js/tree/dadfef18bcac53537741855c99f084152da1fad9). No browser profile or desktop session import is required.

The SDK supports the unofficial **Zalo Web** protocol and an experimental Desktop sign-in and session transport. The installed macOS app has features that still need implementation or live verification. See [operation status and remaining work](docs/operation-status.md), [desktop findings](docs/desktop-evidence.md), [web protocol evidence](docs/web-protocol.md), the [operation index](docs/operations.md), and the [static route index](docs/desktop-route-coverage.md) for the exact scope. Upstream notes that unofficial clients can be restricted by Zalo.

The [authentication guide](docs/authentication.md) maps Web/Desktop sign-in, session storage and trust boundaries. Desktop password login handles caller-entered captcha and security answers, then bootstraps the same API without enrolling a trusted companion. Separate [password recovery](docs/desktop-recovery.md) requires explicit phone confirmation, a user-entered OTP and a new password, preserving known reset receipts if login cannot complete. Password create/change and two-factor settings are explicit account operations; the latter can initiate an SMS/challenge. These password/security flows have offline fixture coverage and remain unverified against the live account.

## Sign in and verify

```sh
npm ci
npm run build
npm run zalo -- login
npm run zalo -- verify
```

Open the temporary PNG path printed by `login`. Scan it in the Zalo phone app and approve the sign-in there. The CLI removes the PNG when sign-in ends. `verify` opens the saved session and reads the profile without printing profile fields. `npm run zalo -- probe` checks QR issuance without scanning or saving credentials.

`npm run zalo -- verify --realtime` also opens the message socket and waits for its initial key frame. Zalo may close another web listener on the account when the check connects.

The CLI saves one session at `~/.config/zalo-personal-sdk/session.json` by default. Set `ZALO_SESSION_PATH` for a separate account or environment. The file contains session cookies in plaintext with owner-only permissions on macOS and Linux. Keep it out of Git, logs, and shared storage. `npm run zalo -- forget` deletes the local file. `PersonalZalo.submitWebSignOut(api)` separately submits the Web login widget's sign-out form. Verify provider revocation before treating that submission as complete. [Web sign-in and sign-out](docs/web-protocol.md)

Desktop sign-in uses `npm run zalo -- desktop-login`, followed by `npm run zalo -- desktop-verify`. Open the temporary PNG printed by the login command and approve it on your phone. `desktop-probe` checks QR issuance and cancels before scanning. `desktop-verify --realtime` explicitly checks the Desktop socket. Desktop credentials, renewal token and any companion private key are saved in plaintext at `~/.config/zalo-personal-sdk/desktop-session.json` with private file permissions. Set `ZALO_DESKTOP_SESSION_PATH` for another location. `desktop-forget` clears this local Desktop record. [Desktop CLI and storage](docs/desktop-session-store.md)

Desktop CLI login stays fresh and does not retain a relink secret. Applications can explicitly select `retainLinkingSecret:true`, save the accepted credentials and secret-bearing companion together, and later pass `relink:{uid,companion}` to the same SDK helper. Secret-bearing records use version 2 and remain owner-only **plaintext**. Post-approval failures expose accepted recovery state and truthful save observations; a pending save must settle before repair. Native/live retained relinking remains unverified. [Complete retained-login example and limits](docs/desktop-relink.md)

## Use from another app

Run `npm pack` here, then install the resulting local `.tgz` in your Node project. The package is ESM and includes TypeScript declarations. The tarball also installs the `zalo-personal` CLI.

```ts
import { FileSessionStore, PersonalZalo, ThreadType } from 'zalo-personal-sdk';

const zalo = new PersonalZalo({ store: new FileSessionStore('/private/path/session.json') });
const api = await zalo.resume();

const profile = await api.fetchAccountInfo();
const friends = await api.getAllFriends();
const groups = await api.getAllGroups();

api.listener.on('error', () => console.error('Zalo listener error'));
api.listener.on('message', (message) => {
  if (!message.isSelf && message.type === ThreadType.User) {
    // Handle a direct message. Avoid logging its contents unless your app needs to.
  }
});
api.listener.start();
// Call api.listener.stop() during shutdown.
```

Call `api.sendMessage(text, threadId, ThreadType.User)` for a direct message or use `ThreadType.Group` for a group. The [echo example](examples/echo.mjs) replies only to `!echo` messages in the single direct conversation configured by `ZALO_ECHO_THREAD_ID`. It runs against the real account when you start it with that setting.

For the saved Desktop session, use the [Desktop echo example](examples/desktop-echo.mjs) and [setup guide](docs/desktop-bot.md). It owns each Desktop connection across bounded reconnects and closes it on shutdown. It sends replies only after you explicitly run it for the selected test conversation; live echo delivery has not been tested.

For your own sign-in screen, call `loginWithQR({ onEvent, signal })` and render the `qr` event’s PNG buffer. `scanned` means the phone still needs to approve. The promise resolves to an authenticated `API` only after the web session and account bootstrap succeed. Expiry and decline end the attempt; start a new one explicitly. QR images and session cookies can grant access, so keep them inside the app’s sign-in flow. For custom secret storage, implement `SessionStore`; without a store the SDK keeps the session in memory. `connect(session)` accepts an SDK session you already hold; `saveSession(api)` saves the API’s current cookie jar to the configured store.

The account’s web listener can be displaced by a second Zalo Web connection. The managed helper stops on displacement. Some media operations require an active listener for upload completion, and image paths require an `imageMetadataGetter` passed as `web.imageMetadataGetter`. `web.agent` applies to the listener. For HTTP proxies, supply a compatible `fetch` implementation. Treat raw API error details, `getContext()`, `getCookie()`, and `cipher_key` as private data.
